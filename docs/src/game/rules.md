# Rules and design

Open Pipeline v0.1 as implemented on `feat/game`. Gameplay numbers live in `[pipeline]` in `game-server/config/game.config.toml` and reach the client on the rules payload — do not hardcode them in TypeScript. **Splitter** (1×1, 1-in/3-out round-robin) and **tunnels** (Factorio-style pairs, `tunnel_max_gap`) ship early relative to the proposal roadmap; later versions (satellite cores, victory) still wait until the current version is reviewed.

## Role in GNUverse

A playful analogy for collaboration and free-software logistics — independent from the blog. Signing in uses the CMS identity provider. Only a signed-in account can place or delete belts.

## Form and loop

Top-down grid. Starter **3×3** sources from `elements.toml` `starter_source_ids` (currently fire and water) and a **5×5** central core. Each core face has three input slots on the central tiles; corners are solid (**12** inputs). Each source emits from a single output on the center of its facing edge. At match start, `world/placement/approach.ts` (`layoutStarterSources`) places those sources from the room seed on clearance-separated approaches around the core in the starter chunk. Map generation reserves non-overlapping rectangular clearance pads around each machine from TOML (`machine_clearance_min`, `core_clearance_extra`); see [Decisions §9](../decisions.md#9-open-pipeline-machines). Players may still place belts on those cells after the match starts. Players drag unidirectional belts and place **divisors** (splitters), **túneis** (tunnel portal pairs), and **combinadores** (craft machines). Player-placed buildings may **share empty port cells** with each other (belt in the gap); that does not link machines. A port must not occupy another building’s body (outputs: exterior slot cell; inputs: approach cell outside the rim), except logistics may propose ports on other bodies when placement rules allow. **Divisors** may touch another building (body–body adjacency) only when an output **plugs** into the other machine’s input slot **with matching travel**; side dumps onto an input tile do not count. **Túneis** may sit body-adjacent only when a machine output feeds the entrance or a machine input accepts the exit; otherwise placement fails. Splitter and tunnel brackets hide only on a real plug; core and combiner brackets always draw (repainted above logistics). Source output brackets stay under the circular body. Placing any non-logistic body on another building’s port occupancy cell stays forbidden. Belts may still sit on port cells. Server routing uses the same travel match for direct machine-to-machine intake. Each cell holds one packet. A splitter absorbs from behind and ejects round-robin to left / forward / right belts. A tunnel entrance absorbs into an underground lane of length `tunnel_max_gap` gap; packets advance one lane per tick and eject at the exit onto a belt ahead. Machine **outputs** (sources, combiners, splitters, tunnel exits) place packets on empty belts that are not facing **inward** (back into the port); outward and perpendicular belts are allowed. Surface belts may cross the gap cells without mixing with the underground flow. Dragging a belt across belts already on the map places a tunnel when the crossed run fits in `tunnel_max_gap`, with a belt on the stroke immediately before the entrance and immediately after the exit. Belts already on the cells between those portals stay on the surface. A machine output plugged into the entrance (its cell is the entrance or the cell behind it) replaces that leading belt, and an input whose approach is the exit replaces the trailing belt, so those ports do not need an extra conveyor tile. Belts separated by one or two empty cells count as one run, because that gap cannot hold an exit, a connecting belt, and the next entrance. A longer run, or a run with no free cell for an entrance or an exit, stays in place: the stroke places belts on the free cells and leaves the crossed cells unchanged. Mergers are not a separate structure — belts that point into the same cell already merge.

The server moves packets simultaneously. Packets do not swap. Machine **inputs** only take packets from the belt cell directly in front of them (one step outside along the opposite of slot travel), regardless of that belt’s facing. A belt on another side that happens to point at the machine is not an input. When that approach belt also has an available forward destination, pull and belt-forward **round-robin** (persisted per approach cell as `pullLast`). When two or three belts feed the same free cell, merge arbitration admits one packet per tick in round-robin order over the inbound sides (stable NESW, at most three inputs; a fourth inbound placement is rejected). Empty inputs are skipped. An open core slot consumes a circle and counts a delivery while that shape’s `received` count is still below its `required` milestone from TOML; once the quota is met, further packets of that shape do not enter the core and remain on the belt. There is no stability bar and no crash: the match keeps running. Later versions keep prior packet demands active; without those supplies, leveling up is impossible. There is no victory screen yet.

## Presentation

Dark background; machine **bodies** are procedural shapes plus “[”-shaped slot brackets from `Machine`, each stroked with `color_outline` at `outline_width_px`. **Core** and **craft** machines use cell-fit rectangles (`color_core` white for the core; combiners use fixed `[[machines]].color`). **Source** uses an inscribed **circle** on its 3×3 footprint filled with the produced element’s catalog `fill` (fallback `color_source`); the output bracket’s back edge overlaps into that circle (see [Decisions §9](../decisions.md#9-open-pipeline-machines)). Black-ink decor SVGs tint when drawn: craft machines and the source use `darkenHex(body, decor_darken_percent)`; the core layers `core-frame.svg` (static) plus counter-rotating `core-gear-outer.svg` / `core-gear-inner.svg` tinted with the accent family (`core_gear_*_ms` in `[pipeline]`). Core gears rotate only while that core is ingesting (and for `core_gear_active_ms` after the last intake); idle gears hold their angle. Splitter and tunnel use hand-drawn arrow decor (`splitter-decor.svg`, `tunnel-entrance-decor.svg` / `tunnel-exit-decor.svg`) that **rotate with facing** for orientation hinting; other machine decor stays upright. Source draws circular-frame `source-decor.svg` on top of body and slot. `color_decor` stays in the palette for future UI but is not the overlay tint. Extended palette keys (`color_surface`, `color_muted`, `color_highlight`, and siblings) are in `[pipeline]` TOML for future UI. The **resource** symbol for each source is screen-space (zoom-independent): it shows the element the source represents (`role` / catalog id, or `shape` when no role), tinted to that element’s `fill` with a dual outline from `[pipeline]` `resource_glyph_outline_*` (outer/inner color, widths, spread), or a filled `color_packet` disk with the same outline when the id is `circle`. Size comes from `glyph_size_px` or `resource_glyph_size_px` in `[pipeline]`. Orbit (`resource_glyph_orbit_px`, `resource_glyph_orbit_ms`) runs while a packet is actively leaving the output cell and for a short hold after the last export (derived from `source_rate_per_minute` in `elements.toml`); otherwise the glyph stays centered on the source — not stamped on the body. Combiners show a static glyph of the last primary output (screen-space, no orbit). While `craftRemaining` counts down, a dual-outlined progress wheel scales with that glyph under camera zoom and fills smoothly between sim ticks (rates from the element catalog). Thick strokes in decor art match `decor_stroke_width`. Belts are fill and chevron only (no outline); track ends are square and stay inside the cell, and chevrons move with the belt until they leave that cell. Belt packets reuse the same outlined glyph / disk helpers as machine-top icons (`fill` plus dual outline). In-room copy is Portuguese. **Core requirements** (version and a grid of demanded shapes with `received / required` counts) live in a room **sidebar**; **Participantes** lists members and collaborators (letter avatars + nicknames from `frame.collaborators`), and per-room **chat** (signed-in send via `POST /api/towers/:id/chat`, history over SSE `chat`; guests read-only with login redirect). Chat limits come from root TOML (`chat_message_max_length`, `chat_history_limit`, `chat_cooldown_ms`). Per-shape totals come from the server frame (`deliveryByShape`, `demands`); required targets come from `elements.toml` (e.g. `default_demand_required` for the interim circle milestone in v0.1). (`CoreRequirementsSidebar`); on narrow viewports the panel sits under the canvas. Git blame on belts is a canvas hover label on desktop and a ~450ms long-press on touch. Product name **Open Pipeline** stays untranslated in UI and metadata titles.

## Version unlock (v0.1 → economy shift)

On **0.1**, when every active demand shape reaches its `required` count, the server auto-advances to **0.2** on the next tick. Unique collaborators no longer gate version unlock (presence and blame still use the collaborator list). Administrators can `POST /api/towers/:id/advance`. All **12** core inputs stay open in v0.1.

Growth uses the **per-player wallet** (passive regen; criteria-based earn later) for belts, machines, and chunk expansion. Version unlock stays **deliveries only**. Chunk cost keys live in `[pipeline]`; per-base spawn odds live on tier-1 rows in `elements.toml`. Buy API and probabilistic outer-source spawn are not fully shipped yet. Preview/buy is **edge-adjacent only**. The starter chunk places `starter_source_ids` (still emit **circle**); other chunks may be empty. Clearance pads apply at generation. See [Coins and map expansion](economy-expansion.md) and [Decisions §11](../decisions.md#11-coins-and-chunk-expansion).

Footprints and machine art rules are locked in [Decisions §9](../decisions.md#9-open-pipeline-machines).

## Stack constraints (do not invent alternatives)

- Static lobby at `/jogo/`; room at `/jogo/torre/?id=<uuid>`.
- Separate Node `game-server`, SQLite, server-authoritative state over **SSE**.
- The grid tick does **not** use Matter.js.
- Do not rename `/jogo/torre/` or `/api/towers`. Do not add a Rust service, WebSockets, or an in-memory-only store.
